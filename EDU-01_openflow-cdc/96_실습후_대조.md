# 96. 실습 후 대조 (Round-trip 검증)

`98_리소스정리.sql` 을 실행한 **직후** 이 문서를 수행합니다.
`95_실습전_기준선.md` 에 적어 둔 값과 대조해 **실습 전 상태로 돌아왔음**을 증명합니다.

> 🔴 **이 문서에는 값이 채워져 있지 않습니다. 의도된 것입니다.**
> "정리했다" 가 아니라 **"없음을 확인했다"** 로 끝나야 합니다.
> 작성자의 값을 전사해 두면 대조 기준이 무의미해집니다.

> 📌 **이 문서가 `98_ PART E` 와 어떤 관계인가**
> 이 문서가 **왕복 검증의 정본**입니다. `98_ PART E` 는 정리 스크립트 안에서
> 곧바로 확인할 수 있도록 같은 쿼리를 두고 있으며, 기록은 이 문서에 남깁니다.
> 두 곳의 쿼리가 어긋나면 **이 문서를 기준으로 맞추십시오.**

**실행 역할:** `ACCOUNTADMIN`
**시점:** `98_` 실행 직후 (미루면 2회차 재실행 검증 기회를 놓칩니다)

## 1. 🔴 잔여물 0 확인 — 접두사 검색

```sql
SHOW DATABASES  LIKE 'OPENFLOW_EDU_%';
SHOW DATABASES  LIKE 'CDC_LAB_%';
SHOW WAREHOUSES LIKE 'OPENFLOW_EDU_%';
SHOW ROLES      LIKE 'OPENFLOW_EDU_%';
SHOW EXTERNAL ACCESS INTEGRATIONS LIKE 'PG_SOURCE_%';
SHOW OPENFLOW DEPLOYMENTS;
SHOW OPENFLOW RUNTIMES   IN ACCOUNT;
SHOW OPENFLOW CONNECTORS IN ACCOUNT;
```

| `CDC_LAB_%` 데이터베이스 | | 0 | |
| `OPENFLOW_EDU_%` 웨어하우스 | | 0 | |

> 객체이므로 `DROP DATABASE` 로 사라지지 않고, 놓치면 계정에 영구히 남습니다.

## 3. 🔴 사용자 속성 원복 확인

`98_` PART C-7 이 실행되었는지 **결과로** 확인합니다.
"원복 구문을 실행했다"는 근거가 되지 않습니다.

```sql
SET my_user = CURRENT_USER();
DESCRIBE USER IDENTIFIER($my_user);

SELECT PARSE_JSON(CURRENT_SECONDARY_ROLES()):value::string AS secondary_roles_after;
```

| 속성 | `95_` §4 실습 전 값 | 정리 후 값 | 일치? |
| :--- | :--- | :--- | :---: |
| `DEFAULT_SECONDARY_ROLES` | | | |
| `DEFAULT_ROLE` | | | |

- 적용한 원복 분기: ☐ 경우 1 (변경 없었음) ☐ 경우 2 (`UNSET`) ☐ 경우 3 (`SET <원래 값>`)

> 🔴 두 값이 다르면 **왕복이 완성되지 않았습니다.** `95_` §4 의 분기표를 다시
> 보고 해당 구문을 실행하십시오. 이 항목은 `DROP` 으로 해결되지 않습니다.

## 4. COMMENT 태그 기반 광역 검색 (보조)

접두사를 놓친 객체를 잡기 위한 2차 검사입니다.

```sql
SHOW DATABASES;
SELECT "name", "comment"
FROM TABLE(RESULT_SCAN(LAST_QUERY_ID()))
WHERE "comment" ILIKE '%[openflow-edu]%';
```

```sql
SHOW WAREHOUSES;
SELECT "name", "comment"
FROM TABLE(RESULT_SCAN(LAST_QUERY_ID()))
WHERE "comment" ILIKE '%[openflow-edu]%';
```

- 태그 `[openflow-edu]` 가 남은 객체 수: `______` (기대: 0)

> ⚠️ `SNOWFLAKE.ACCOUNT_USAGE` 뷰는 최대 2~3시간 지연되므로 정리 직후 확인에
> 부적합합니다. 즉시 확인은 위처럼 `SHOW` + `RESULT_SCAN` 으로 하십시오.
> `RESULT_SCAN` 의 컬럼명은 큰따옴표로 인용해야 합니다.
> 계정 에디션에 따라 일부 `ACCOUNT_USAGE` 뷰가 없을 수 있습니다.
