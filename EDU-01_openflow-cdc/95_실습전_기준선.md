# 95. 실습 전 기준선 (Baseline)

정리(`98_`) 후 이 기록과 대조해 **실습이 계정에 흔적을 남기지 않았음**을 증명합니다.

> 🔴 **이 문서에는 값이 채워져 있지 않습니다. 의도된 것입니다.**
> 계정 상태는 계정마다 다르고 시간이 지나면 달라지므로, 작성자의 값을 전사해 두면
> 즉시 거짓이 되어 대조 기준으로 쓸 수 없습니다.
> **아래 쿼리를 직접 실행해 빈칸을 채우십시오.**

> 📌 **이 문서가 `02_` 와 어떤 관계인가**
> 같은 스냅샷 쿼리가 `02_사전준비_및_권한구성.sql` 의 `STEP 0-6` 에도 있습니다.
> 두 곳 중 **어느 쪽을 실행해도 됩니다.** 이 문서를 별도로 둔 이유는,
> `02_` 는 350줄이 넘는 스크립트이고 스냅샷이 그 중간에 있어서
> **위에서부터 실행하다 스크롤로 지나치기 쉽기 때문**입니다.
> 스냅샷을 건너뛰면 그 뒤의 모든 정리 검증이 대조 기준을 잃습니다.
> 별도 문서로 두면 "건너뛰었다"는 사실이 눈에 보입니다.

**실행 역할:** `ACCOUNTADMIN`
**성격:** 전부 **조회 전용**입니다. 이 문서의 어떤 쿼리도 계정을 변경하지 않습니다.

## 1. 🔴 접두사 충돌 검사 — 가장 먼저

실습은 아래 접두사로 객체를 만듭니다. **이미 같은 이름이 있으면 실습을
진행하지 마십시오.** 기존 객체를 재사용하면 정리로 되돌릴 수 없습니다.

```sql
SHOW DATABASES  LIKE 'OPENFLOW_EDU_%';
SHOW DATABASES  LIKE 'CDC_LAB_%';
SHOW WAREHOUSES LIKE 'OPENFLOW_EDU_%';
SHOW ROLES      LIKE 'OPENFLOW_EDU_%';
SHOW EXTERNAL ACCESS INTEGRATIONS LIKE 'PG_SOURCE_%';
```

| 검사 대상 | 결과 행 수 (기대: 0) | 충돌 시 조치 |
| :--- | :---: | :--- |
| `OPENFLOW_EDU_%` 데이터베이스 | | 접두사 변경 (예: `OPENFLOW_EDU2_`) |
| `CDC_LAB_%` 데이터베이스 | | 접두사 변경 |
| `OPENFLOW_EDU_%` 웨어하우스 | | 접두사 변경 |
| `OPENFLOW_EDU_%` 역할 | | 접두사 변경 |
| `PG_SOURCE_%` EAI | | 접두사 변경 |

> 🔴 하나라도 0행이 아니면 **여기서 멈추고** 접두사를 바꾸거나 그 객체의
> 정체를 확인하십시오. `CREATE ... IF NOT EXISTS` 는 기존 객체를 그대로
> 쓰게 만들며, 정리 단계에서 **사용자 자산을 삭제**할 수 있습니다.

## 4. 🔴 변경되는 사용자 속성 — 이 절이 가장 중요합니다

`02_` STEP 1-5 는 **실습 수행자 본인의 사용자 속성을 변경합니다.**
이것은 신규 객체 생성이 아니라 **기존 객체의 변경**이므로
`DROP` 으로 되돌아가지 않습니다. **지금 값을 적어 두지 않으면 원복할 수 없습니다.**

```sql
SET my_user = CURRENT_USER();
DESCRIBE USER IDENTIFIER($my_user);

SELECT PARSE_JSON(CURRENT_SECONDARY_ROLES()):value::string AS secondary_roles_before;
```

| 속성 | 실습 전 값 (반드시 기록) | 원복 분기 |
| :--- | :--- | :--- |
| `DEFAULT_SECONDARY_ROLES` | | 아래 3분기 참고 |
| `DEFAULT_ROLE` | | 아래 3분기 참고 |

**원복 분기 — `98_` PART C-7 에서 이 판단을 씁니다.**

| 경우 | 실습 전 값 | 정리 시 실행할 것 |
| :--- | :--- | :--- |
| 1 | 이미 `('ALL')` 이었다 | **아무것도 하지 않습니다.** 변경 자체가 불필요했습니다 |
| 2 | 미설정 / NULL 이었다 | `ALTER USER … UNSET DEFAULT_SECONDARY_ROLES;` |
| 3 | 명시적으로 다른 값이었다 | `ALTER USER … SET DEFAULT_SECONDARY_ROLES = <원래 값>;` |

> 🔴 `UNSET` 과 `SET <원래 값>` 은 **다른 결과**를 냅니다. 어느 쪽인지는
> 위 표의 실습 전 값으로만 판단할 수 있습니다. 값을 적지 않고 실습을
> 진행하면 왕복 가능성이 깨집니다.

> 💡 `DESCRIBE USER` 출력에 해당 속성이 보이지 않는 경우가 있습니다.
> 그때는 "출력에 없었다"는 사실 자체를 기록해 두십시오. 그것도 정보입니다.

## 5. 🔴 외부 시스템(소스 DB) 사전 상태

Snowflake 정리로는 되돌아가지 않는 항목입니다.
`04_`(PostgreSQL) 또는 `10_`(MySQL) 을 수행하기 **전에** 기록하십시오.

### PostgreSQL 경로

```sql
SHOW wal_level;
SELECT * FROM pg_replication_slots;
SELECT * FROM pg_publication;
SELECT usename FROM pg_user WHERE usename = 'openflow_repl';
```

| 항목 | 실습 전 값 | 원복 방법 |
| :--- | :--- | :--- |
| `wal_level` | | 실습 전 값으로 복귀 + **서버 재시작 필요** |
| 기존 복제 슬롯 목록 | | 실습이 만든 것만 `pg_drop_replication_slot()` |
| 기존 퍼블리케이션 목록 | | 실습이 만든 것만 `DROP PUBLICATION` |
| `openflow_repl` 사용자 존재 여부 | | 없었다면 `DROP USER` |

### MySQL 경로

```sql
SHOW VARIABLES LIKE 'binlog_format';
SHOW VARIABLES LIKE 'binlog_row_image';
SHOW VARIABLES LIKE 'log_bin';
SELECT user, host FROM mysql.user WHERE user = 'openflow_repl';
```

| 항목 | 실습 전 값 | 원복 방법 |
| :--- | :--- | :--- |
| `binlog_format` | | 실습 전 값으로 `SET GLOBAL` |
| `binlog_row_image` | | 같은 방식 |
| `log_bin` | | my.cnf 수정 + **재시작 필요** |
| `openflow_repl` 사용자 | | 없었다면 `DROP USER` |

> 🔴 **복제 슬롯은 방치하면 WAL 이 무한 축적되어 소스 디스크를 고갈시킵니다.**
> 실습 전에 존재하던 슬롯과 실습이 만든 슬롯을 구분할 수 있도록
> 위 목록을 반드시 기록하십시오.
