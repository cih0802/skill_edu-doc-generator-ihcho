# Openflow Gen 2로 CDC 구현하기 — 교육자료 정리본

## 1. 학습 목표

이 실습을 마치면 다음을 할 수 있습니다.

- Openflow Gen 2의 객체 모델(Deployment / Runtime / Connector)을 SQL로 설명하고 생성할 수 있다.
- 최소 권한 원칙에 따라 Openflow 전용 Role 3종(admin / DE / execute-as)을 구성할 수 있다.
- 외부 PostgreSQL의 논리 복제(logical replication)를 CDC 소스로 설정할 수 있다.
- Network Rule + External Access Integration(EAI)으로 Runtime의 외부 egress를 허용할 수 있다.
- `OPENFLOW_POSTGRES_CDC` 커넥터를 SQL로 생성·설정·기동하고, 상태 머신을 따라 문제를 진단할 수 있다.
- 소스 테이블의 INSERT / UPDATE / DELETE가 Snowflake 대상 테이블에 반영되는 것을 **직접 확인**할 수 있다.
- 실습 리소스를 안전하게 정리할 수 있다.

### 완료 시 달성 상태

```
[외부 PostgreSQL]  --(논리 복제 / WAL)-->  [Openflow Runtime]  --(Snowpipe Streaming)-->  [Snowflake 대상 DB]
   public.customers                          PG_CDC_CONNECTOR                    CDC_LAB_PG_DB.PUBLIC.CUSTOMERS
   public.orders                              (RUNNING)                          CDC_LAB_PG_DB.PUBLIC.ORDERS
```
소스에서 `UPDATE customers SET ...` 실행 → 수 초~수십 초 내 Snowflake 테이블에 반영.

## 2. 사전 준비물

### 2.1 Snowflake 측

| 항목 | 요구사항 | 확인 방법 |
|------|----------|-----------|
| Openflow Gen 2 활성화 | `SHOW OPENFLOW CONNECTOR DEFINITIONS` 가 행을 반환 | 02번 문서 STEP 0 |
| 권한 | `ACCOUNTADMIN` (또는 Role/DB/Integration/Compute Pool 생성 권한) | `SELECT CURRENT_ROLE()` |
| 약관 동의 | Snowsight **Admin » Terms** 에서 Openflow / Snowflake Connector Terms 동의 | 02번 문서 STEP 0 |
| Deployment 여유분 | 계정당 Snowflake Deployment 최대 **3개** | `SHOW OPENFLOW DEPLOYMENTS` |
| Region | Openflow 지원 리전 (AWS/Azure/GCP Commercial) | `SELECT CURRENT_REGION()` |

> ⚠️ **Trial 계정 주의**: Snowflake 공식 문서는 "Openflow는 Trial 계정에서 자동으로 사용 가능하지 않으며, 활성화를 위해 계정 팀에 문의해야 한다"고 명시합니다. Gen 2 커넥터 정의가 조회된다고 해서 `CREATE OPENFLOW DEPLOYMENT` 가 반드시 성공하는 것은 아닙니다. 02번 문서의 STEP 0 게이트에서 이를 먼저 확인합니다.

### 2.2 소스 측 (실습의 실질적 전제조건)

| 항목 | 요구사항 |
|------|----------|
| PostgreSQL 인스턴스 | **버전 및 관리형 여부 무관하나, 반드시 퍼블릭 인터넷에서 접근 가능(DNS 해석 가능)해야 함** |
| 관리자 권한 | `ALTER SYSTEM` 또는 파라미터 그룹 수정 권한 (재시작 포함) |
| 권장 환경 | AWS RDS PostgreSQL (퍼블릭 액세스 활성), GCP Cloud SQL, 또는 퍼블릭 IP를 가진 EC2/VM |

> ⚠️ **가장 흔한 실습 실패 원인**: `CREATE NETWORK RULE ... MODE = EGRESS` 는 **생성 시점에 `VALUE_LIST` 의 모든 호스트를 DNS 검증**합니다. 해석되지 않는 호스트(placeholder, 오타, 중지된 DB)를 넣으면 `invalid value for property 'VALUE_LIST'` 로 실패합니다. 따라서 소스 DB는 실습 시작 전에 **실제로 기동되어 있고 이름이 해석되어야** 합니다.
>
> 사설망/온프레미스 소스는 이 실습 범위 밖이며, Data Connectivity Proxy(DCP) 또는 outbound PrivateLink(Business Critical 이상)가 필요합니다.

## 3. 아키텍처 개요

### 3.1 Openflow Gen 2 객체 모델

```
ACCOUNT
├── OPENFLOW DEPLOYMENT  (계정 레벨, 데이터 플레인 컨테이너)
│      └── OPENFLOW RUNTIME  (스키마 레벨, 실제 NiFi 실행 노드)
│             └── OPENFLOW CONNECTOR  (스키마 레벨, 커넥터 인스턴스)
│                    └── config.json  (버전 관리되는 설정 파일)
│
├── EXTERNAL ACCESS INTEGRATION  ← NETWORK RULE  (Runtime의 외부 egress 허용)
├── SECRET (GENERIC_STRING)      (소스 DB 비밀번호)
└── ROLE × 3                     (admin / DE / execute-as)
```

### 3.2 객체 대장 (Object Registry) — 정리 절차의 계약서

> 이 표는 **실습에서 만들거나 변경하는 모든 것**의 목록입니다.
> 여기에 없는 객체를 만들지 않고, 여기 있는 모든 행이 `98_리소스정리.sql` 에서
> 삭제 또는 원복되어야 합니다. **두 문서가 어긋나면 계정에 잔여물이 남습니다.**

#### (b) 기존 객체의 속성 변경 — 삭제가 아니라 **원복** 대상

> ⚠️ 신규 생성이 아니므로 `DROP` 으로 되돌아가지 않습니다.
> **실습 전 값을 `02_` STEP 0-6 에서 반드시 기록해 두십시오.**

| 대상 | 변경 내용 | 생성 문서 | 원복 방법 |
|------|-----------|-----------|-----------|
| 현재 사용자 | `DEFAULT_SECONDARY_ROLES = ('ALL')` | `02_` STEP 1-5 | `98_` PART C-7 — `ALTER USER … UNSET DEFAULT_SECONDARY_ROLES` (실습 전 값에 따라 분기) |
| 현재 사용자 | `DEFAULT_ROLE` (선택 — 주석 처리 제공) | `02_` STEP 1-5 | `98_` PART C-7 — 실습 전 값으로 `SET` |
| Deployment | `EVENT_TABLE` 지정 | `03_` STEP 4 | Deployment 삭제 시 함께 사라짐 |
| Runtime | `EXTERNAL_ACCESS_INTEGRATIONS` 지정 | `05_` | `98_` PART C-2 — `UNSET EXTERNAL_ACCESS_INTEGRATIONS` |

세션 레벨 변경(`USE SECONDARY ROLES ALL`)은 세션 종료 시 자동으로 사라지므로 원복 대상이 아닙니다.

#### (c) Snowflake 외부 리소스 — 놓치면 사용자 환경에 문제가 남습니다

| 종류 | 이름 | 스코프 | 생성 문서 | 정리 방법 | 방치 시 결과 |
|------|------|--------|-----------|-----------|-------------|
| PG 복제 슬롯 | (커넥터가 자동 생성) | 소스 DB | 커넥터 기동 시 | `pg_drop_replication_slot()` | **WAL 무한 축적 → 소스 디스크 고갈** |
| PG PUBLICATION | `openflow_pub` | 소스 DB | `04_` | `DROP PUBLICATION` | 불필요한 발행 잔존 |
| PG 테이블 | `public.customers`, `public.orders` | 소스 DB | `04_` | `DROP TABLE` | 스토리지 |
| PG 사용자 | `openflow_repl` (LOGIN REPLICATION) | 소스 DB | `04_` | `REVOKE` → `DROP USER` | **미사용 자격증명 잔존** |
| PG 설정 | `wal_level = logical` (RDS `rds.logical_replication`, Cloud SQL `cloudsql.logical_decoding`) | 소스 DB | `04_` | 원래 값으로 되돌리고 **재시작** | WAL 생성량 증가 |
| PG 접근 제어 | `pg_hba.conf` 항목, `listen_addresses` | 소스 DB | `04_` | 항목 제거 후 reload | **불필요한 접근 경로 잔존** |
| MySQL 사용자 | `openflow_repl@%` | 소스 DB | `10_` | `DROP USER` | 미사용 자격증명 잔존 |
| MySQL 스키마 | `cdclab` | 소스 DB | `10_` | `DROP DATABASE` | 스토리지 |
| MySQL 설정 | `log_bin`, `binlog_format`, `binlog_row_metadata` 등 | 소스 DB | `10_` | 원래 값으로 되돌리고 **재시작** | binlog 누적, 성능 영향 |
| 로컬 파일 | JDBC 드라이버 JAR, 편집한 `config.json` | 로컬 | `07_` | 파일 삭제 (선택) | 없음 (비밀번호가 담겼다면 삭제 권장) |

#### (d) 명명 규칙 — 잔여물을 한 번에 찾기 위한 장치

- Snowflake 객체 접두사: `OPENFLOW_EDU_` (인프라), `CDC_LAB_` (대상), `PG_SOURCE_` (네트워크/Secret)
- 모든 객체의 `COMMENT` 에 공통 태그 **`[openflow-edu]`** 를 포함
- 덕분에 정리 후 `SHOW … LIKE 'OPENFLOW_EDU_%'` 와 태그 검색으로 잔여물을 일괄 확인할 수 있습니다 (`98_` PART E)

> **중요**: 인프라 DB(`OPENFLOW_EDU_DB`)와 대상 DB(`CDC_LAB_PG_DB`)를 분리하는 것은 Snowflake 권장 사항입니다. 커넥터는 소스 스키마/테이블 이름을 그대로 사용해 대상 스키마·테이블을 **자동 생성**하므로, 인프라 DB를 대상으로 지정하면 이름 충돌 위험이 있습니다.

### 3.3 커넥터 상태 머신

```
CREATING → STOPPED → STARTING → RUNNING
                ↑         ↓         ↓
                ←── STOPPING ←──────┘
                ↑                   ↓
                ←───────── START_FAILED

STOPPED → (COMMIT) → UPDATE_FAILED
STOPPED → TERMINATE → DELETED → DROP
```

- **전이 상태**(`CREATING`, `STARTING`, `STOPPING`)에서는 명령을 보내지 말고 대기합니다.
- **안정 상태**: `STOPPED`, `RUNNING`, `START_FAILED`, `UPDATE_FAILED`, `DELETED`
- 대기는 `SYSTEM$WAIT_FOR_OPENFLOW_CONNECTOR_STATUS(초, '목표상태', 'FQN')` 로 합니다.

## 4. 핵심 개념

### 4.1 CDC (Change Data Capture)

소스 DB의 변경 로그를 읽어 대상으로 전파하는 방식. 전체 재적재(full reload) 대비 지연이 낮고 소스 부하가 작습니다.

| 소스 | 변경 로그 메커니즘 | 필수 설정 |
|------|-------------------|-----------|
| PostgreSQL | WAL + 논리 복제 슬롯 | `wal_level = logical`, PUBLICATION, REPLICATION 권한 |
| MySQL | binary log | `log_bin=on`, `binlog_format=row`, `binlog_row_metadata=full` |

### 4.2 Ingestion Type — `full` vs `incremental`

| 값 | 동작 | 사용 시점 |
|----|------|-----------|
| `full` | 스냅샷(초기 전량 적재) → 이후 CDC | **최초 설치. 이 실습에서 사용** |
| `incremental` | CDC만. 스냅샷 생략 | 재설치 시 이미 적재된 데이터를 다시 받지 않으려는 경우 |

### 4.3 Identity Key — UPDATE/DELETE 복제의 전제

대상에 UPDATE/DELETE를 반영하려면 소스 테이블에 식별 키가 필요합니다.

- **PostgreSQL**: PK + `REPLICA IDENTITY DEFAULT` (일반적) 또는 UNIQUE 인덱스 + `REPLICA IDENTITY USING INDEX`
- **MySQL**: PK, 또는 NOT NULL UNIQUE 인덱스 (InnoDB가 자동 승격)
- 둘 다 없으면 **INSERT만 복제**되고 UPDATE/DELETE는 유실됩니다. 실습 테이블에는 반드시 PK를 둡니다.

### 4.4 SNOWFLAKE_MANAGED 인증

Openflow Runtime이 Snowflake에 쓸 때의 권장 인증 방식. 키페어를 만들거나 회전할 필요 없이 SPCS 세션 토큰을 자동으로 사용합니다. 이 실습은 전부 `SNOWFLAKE_MANAGED` 를 사용합니다.

### 4.5 execute-as role

커넥터가 실행 시점에 **실제로 사용하는 Role**. 세션 Role이나 Runtime 스키마 권한이 아니라 이 Role의 그랜트가 적용됩니다. 따라서 대상 DB의 `CREATE SCHEMA`, Warehouse의 `USAGE, OPERATE`, Secret의 `READ` 는 반드시 execute-as role에 부여해야 합니다.

> Warehouse에 `OPERATE` 가 필요한 이유: 커넥터가 **suspend된 Warehouse를 스스로 재개**해야 하기 때문입니다. `USAGE` 만 주면 자동 재개 실패로 MERGE가 멈춥니다.

### 문서 분리 이유

실습은 SQL 한 문서로 끊김 없이 진행되지 않습니다. 전환 지점이 두 곳 있습니다.

1. **03 → 04**: Runtime을 만든 뒤, Network Rule 생성에 필요한 **소스 호스트명**을 얻기 위해 소스 DB를 먼저 준비해야 합니다(외부 작업).
2. **06 → 07**: JDBC 드라이버 JAR 업로드와 `config.json` 편집은 SQL만으로 되지 않습니다(파일 다운로드 + 로컬 편집 + 스테이지 업로드).
3. **11 / 98**: 트러블슈팅은 실습 중 **참조**하는 문서이고 정리는 실습 후 **실행**하는 SQL 문서입니다. 성격이 달라 분리했습니다.

## 7. 비용 주의

- **Deployment 자체에는 별도 과금이 없습니다.** 크레딧을 소비하는 것은 **활성 Runtime**입니다.
- Runtime은 자동 suspend되지 않습니다. 실습이 끝나면 `98_리소스정리.sql` 의 정리 절차를 반드시 수행하십시오.
- 실습을 이어서 할 예정이면 `98_` PART A(일시 중단)만으로도 크레딧 소비를 멈출 수 있습니다.
- Warehouse는 `AUTO_SUSPEND = 60` 으로 생성해 유휴 비용을 줄입니다.

### 검토 5 — 미검증 항목 (정직한 고지)

|------|-------------|

#### 개선 후에도 남아 있는 한계 (숨기지 않습니다)

- **핵심 경로는 여전히 실행 미검증**입니다. `CREATE OPENFLOW DEPLOYMENT` / `RUNTIME` / `CONNECTOR`, `CREATE NETWORK RULE`, 커넥터 기동과 적재는 외부 소스 DB와 크레딧이 필요해 검증하지 못했습니다. 5차 검토의 미검증 목록이 그대로 유효합니다.
- `98_` 의 **`DROP` 계열 구문은 전부 미검증**입니다. 삭제 대상 객체가 계정에 없어 컴파일조차 되지 않습니다. 문법은 공식 문서로 대조했고, 전 구문을 주석 처리해 오작동 위험을 줄였습니다.
- `98_` **PART D(외부 리소스)** 는 소스 DB에서 실행하는 것이라 이 환경에서 검증할 수 없습니다.
- MySQL 경로(`10_`)는 **부록 수준**입니다. 대상 DB 이름이 `CDC_LAB_PG_DB` 로 PostgreSQL 기준이며, MySQL 전용 전체 문서 세트는 없습니다.
- 객체 대장과 `98_` 의 **1:1 대조는 사람이 읽어 확인**했습니다. 자동 검증 스크립트는 없습니다.
