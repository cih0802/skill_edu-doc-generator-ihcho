## 3. 이 폴더 문서에 남아 있는 결함 (보관 시점 기준)

전부 **실제 실행 검증**으로 확인된 것이다. 상세는 활성 세트
`01_교육자료_정리본.md` 의 **7차 개선(완주 검증)** 절을 보라.

| 심각도 | 원본 위치 | 결함 |
| :--- | :--- | :--- |
| 🔴 | `98_` PART B·C-3·F | **`DROP OPENFLOW DEPLOYMENT` 만으로는 정리되지 않는다.** ACTIVE 상태에서 `DROP` 은 `DROP not allowed while OPENFLOW DEPLOYMENT ... is in ACTIVE status` 로 거부된다. 이 절차를 그대로 따르면 **Deployment 가 계정에 잔존**한다 (왕복 불가). `ALTER ... TERMINATE` → 대기 → `DROP` 이 필요하다 |
| 🔴 | `01_` 2.1, `03_` 헤더 | **트라이얼 경고의 대상이 틀렸다.** "Trial 에서 `CREATE OPENFLOW DEPLOYMENT` 가 실패할 수 있다" 를 게이트로 삼았으나 **실제로는 성공**했다. 진짜 차단 지점은 `05_` 의 `CREATE EXTERNAL ACCESS INTEGRATION` (`External access is not supported for trial accounts`). 학습자를 잘못된 곳에서 멈추게 하고 진짜 벽은 예고하지 않았다 |
| 🟡 | `03_` STEP 2-1 | `SYSTEM$WAIT_FOR_STABLE_OPENFLOW_DEPLOYMENTS` 를 "값을 반환하지 않는다" 고 기술. 실제로는 **`'OK'` 를 반환**한다 |
| 🟡 | `03_` STEP 4 | `DESCRIBE OPENFLOW DEPLOYMENT` 로 `EVENT_TABLE` 을 확인하라고 안내하나 **출력에 그 열이 없다.** 확인 불가능한 검증을 지시했다 |
| 🟡 | `02_`, `03_`, `06_` | 검증 상태가 "컴파일 검증" / "미검증" 으로만 표기되어 있었다. 실제로는 전부 실행 가능했다 (`GRANT CREATE OPENFLOW DEPLOYMENT` 포함) |
| 🟡 | `06_` | Runtime 이 전이 상태(`UPDATING`)일 때 커넥터 조작이 거부되는 제약이 기술되지 않았다 |
