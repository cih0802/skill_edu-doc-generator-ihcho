## 검증 상태 (2026-09-28, 실습 완주)

- ✅ `snow stage copy <ASCII 파일명>.pdf @DOCRAG_DB.RAW.DOC_STAGE/manuals/` — 실제 실행, `UPLOADED`
- 🔴 `snow stage copy <한글 파일명>.pdf ...` — **실제 실행에서 실패** (아래 [2-1] 참고)
- ✅ `AUTO_REFRESH = TRUE` 반영 — 실제 관찰. 단 **즉시가 아니었다**: 업로드 50초 뒤 0행, 약 2분 뒤 반영
- ✅ 업로드 후 스트림 `SYSTEM$STREAM_HAS_DATA = TRUE` — 실제 실행
- ⚠️ Snowsight UI 드래그앤드롭 업로드 — 화면 조작은 SQL 실행으로 확인할 수 없어 미검증

# 04. 문서 업로드 (Snowflake 외부 / 로컬·UI 작업)

이 단계는 로컬 파일을 올리는 작업이라 SQL 워크시트만으로 진행되지 않습니다.
그래서 별도 문서로 분리했습니다.

- **예상 소요 시간**: 약 10분
- **선행**: `03_스테이지_및_증분감지.sql` (`DOC_STAGE` 존재)
- **후행**: `05_파싱_및_Snowpark청킹.sql`

---

## 1. 업로드할 문서

| 항목 | 권장 | 💰 비용 관점 |
|------|------|------|
| 형식 | PDF (텍스트 기반) | 스캔 이미지 PDF 도 되지만 품질은 원본에 좌우됩니다 |
| 건수 | **2~3건** | `AI_PARSE_DOCUMENT` 는 **페이지 수로 과금**됩니다 |
| 페이지 | 문서당 10페이지 이하 | 대용량 문서는 먼저 필요한 페이지만 고르십시오 (`page_filter`) |
| 내용 | 설비 매뉴얼, 운영 지침, 장애 대응 절차 등 | — |

> 🔴 **실제 기밀·개인정보가 든 문서를 실습에 쓰지 마십시오.** 이 실습은 마스킹을 다루지
> 않습니다. (RAG 보안은 EDU-02 자료가 다룹니다)

**교육용 샘플이 없다면** 다음 두 가상 문서를 만들어 쓰십시오. 작성자는 Python
`reportlab` + CID 폰트(`HYSMyeongJo-Medium`)로 A4 1쪽짜리 한국어 PDF 2건을 만들어 검증했습니다.

| 파일명 (ASCII 권장) | 내용 |
|------|------|
| `XR-200_pump_manual.pdf` | 가상 원심 펌프 XR-200 — 정격 유량, 윤활유·씰 교체 주기, 진동 기준, 경보 E-17, 점검 표 |
| `DC-9_cooling_guide.pdf` | 가상 데이터센터 DC-9 냉각 지침 — 급기 온도 기준, 칠러 비상 절차, 경보 C-42 → XR-200 참조 |

> 두 문서가 서로를 참조하도록(C-42 → XR-200) 만든 이유: 08_ 에서 **두 문서에 걸친 질문**을
> 검색이 제대로 모으는지 확인하기 위해서입니다.

---

## 2. 업로드 방법

### 옵션 A — Snowflake CLI (권장, 작성자가 실행 검증한 경로)

로컬 터미널에서 실행합니다. Snowsight 워크시트에서는 `PUT` 을 실행할 수 없습니다.

```bash
snow stage copy ./XR-200_pump_manual.pdf @DOCRAG_DB.RAW.DOC_STAGE/manuals/ --role DOCRAG_ADMIN_RL
```

> 💡 두 번째 문서(`DC-9_cooling_guide.pdf`)는 **지금 올리지 마십시오.** 06_ 에서 증분 처리를
> 확인할 때 올립니다. 지금은 1건만 올립니다.

#### 🔴 [2-1] 한글 파일명은 CLI 업로드가 실패했습니다 (실측)

```
snow stage copy "XR-200_펌프_유지보수_매뉴얼.pdf" @DOCRAG_DB.RAW.DOC_STAGE/manuals/
→ syntax error line 1 at position 46 unexpected '@DOCRAG_DB.RAW.DOC_STAGE/manuals/'.
```

같은 파일을 ASCII 이름으로 복사하자 `UPLOADED` 되었습니다. CLI 가 만드는 `PUT` 구문의
파일 경로 처리 문제로 보이며, 원인은 공식 문서로 확인하지 못했습니다(CLI 버전에 따라 다를
수 있음). **파일명은 영문·숫자·하이픈·밑줄로 바꾸어 올리십시오.** 한글 제목은 문서 본문에
있으므로 검색 품질에는 영향이 없습니다.

### 옵션 B — Snowsight UI

1. **Data » Databases** → `DOCRAG_DB` » `RAW` » **Stages** » `DOC_STAGE`
2. 우측 상단 **+ Files** → 경로에 `manuals/` 입력 → 파일 선택 → **Upload**
3. 우측 상단 역할이 `DOCRAG_ADMIN_RL` 인지 확인하십시오. 다른 역할이면 스테이지가 보이지 않습니다.

> ⚠️ 이 경로는 화면 조작이라 작성자가 검증하지 못했습니다.

## 3. 반영 확인 — SQL 워크시트로 돌아와 실행

```sql
USE ROLE DOCRAG_ADMIN_RL;
USE WAREHOUSE DOCRAG_IHCHO_WH;

-- (1) 디렉터리 테이블 — AUTO_REFRESH 가 반영되면 파일이 보입니다
SELECT RELATIVE_PATH, SIZE, MD5, LAST_MODIFIED
FROM DIRECTORY(@DOCRAG_DB.RAW.DOC_STAGE);

-- (2) 스트림 — 새 파일이 잡혀야 합니다
SELECT SYSTEM$STREAM_HAS_DATA('DOCRAG_DB.RAW.DOC_STAGE_STREAM') AS HAS_DATA;   -- TRUE
SELECT RELATIVE_PATH, METADATA$ACTION FROM DOCRAG_DB.RAW.DOC_STAGE_STREAM;      -- INSERT 1행
```

### (1) 이 0행이면 — AUTO_REFRESH 지연입니다

작성자 계정에서는 **업로드 약 50초 뒤에도 0행이었고, 약 2분 뒤에 반영**되었습니다.
기다리지 않으려면 수동으로 갱신하십시오. 결과는 같습니다.

```sql
ALTER STAGE DOCRAG_DB.RAW.DOC_STAGE REFRESH;
```

> 이 지연값은 1회 관찰이며 보장값이 아닙니다.

## 🧹 리소스 정리

이 단계는 새 객체를 만들지 않습니다. 올린 파일은 `DOC_STAGE` 를 지우면 함께 사라집니다
(`98_리소스정리.sql`). 파일만 지우려면:

```sql
REMOVE @DOCRAG_DB.RAW.DOC_STAGE/manuals/;
```

로컬에서 만든 샘플 PDF 는 직접 삭제하십시오.
