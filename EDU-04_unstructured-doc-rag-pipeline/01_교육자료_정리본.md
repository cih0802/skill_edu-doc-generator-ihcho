## 3. 아키텍처와 비용 최적화 설계

```
 로컬 PDF ──snow stage copy──▶ @RAW.DOC_STAGE  (SSE, DIRECTORY AUTO_REFRESH)
                                   │  디렉터리 테이블
                                   ▼
                          RAW.DOC_STAGE_STREAM ──(WHEN HAS_DATA)──▶ TSK_INGEST_DOCS  [Triggered, DOCRAG_WH]
                                                                         │ CALL
                                                                         ▼
  ┌──────────────── CURATED.SP_INGEST_NEW_DOCS ───────────────────────────────────────┐
  │ stream → DOC_INBOX → (삭제분 청크 제거)                                           │
  │   → MD5 가 처음인 파일만 AI_PARSE_DOCUMENT(LAYOUT) ─▶ DOC_PARSED  | 실패 ▶ DOC_PARSE_ERRORS │
  │   → CHUNK_TECH_DOC (Snowpark Python UDTF) ─▶ DOC_CHUNKS                           │
  │   → PIPELINE_RUN_LOG                                                              │
  └───────────────────────────────────────────────────────────────────────────────────┘
                                   │
                  SERVING.V_SEARCH_SOURCE (MD5 사본 제외)
                                   ▼
            SERVING.DOC_SEARCH_SVC  (arctic-embed-l-v2.0, TARGET_LAG 1 day, AUTO_SUSPEND 1800)
                                   ▼
   질문 ─▶ SERVING.SP_ASK ─ 캐시 적중? ─ yes ─▶ ANSWER_CACHE 반환 (LLM 0회)
     (08_, 학습용 조립형)       └ no ─▶ SEARCH_PREVIEW top-k ─▶ AI_COMPLETE(max_tokens) ─▶ 답+출처
   질문 ─▶ SERVING.DOC_AGENT (10_, Cortex Agent) ─ cortex_search 도구(DOC_SEARCH_SVC) ─▶ 답+인용
                                   ▼
            SERVING.SP_EVALUATE_RAG (Snowpark DataFrame) ─▶ EVAL_RESULT
```

### 3.1 비용 요인별 절감 장치

| 비용 요인 | 과금 단위 (공식 문서) | 이 자료의 절감 장치 | 위치 |
|-----------|------|------|------|
| 웨어하우스 | 가동 시간 | XS, 60초 자동중지, 초기 중지, **Gen1·QAS off 명시**, 쿼리 타임아웃, 리소스 모니터 3 크레딧 | 02_ |
| 문서 파싱 | 페이지 | **MD5 단위 1회 파싱**, 사본 재사용, 실패 파일 격리(반복 과금 방지), 파싱 결과 보관 → 재청킹 무과금 | 05_ |
| 청킹 | 웨어하우스 | LLM 대신 **Python UDTF** (토큰 0) | 05_ |
| 증분 처리 | 웨어하우스 | **Triggered Task** — 이벤트 전 컴퓨트 미사용 | 06_ |
| 임베딩 | 토큰 | 사본 제외 원천 뷰, 원천 규칙을 서비스 생성 전에 확정 | 07_ |
| 검색 서빙 | 서비스가 떠 있는 시간 | **AUTO_SUSPEND 1800초**, 실습 후 SUSPEND/DROP | 07_, 98_ |
| LLM 생성 | 입력+출력 토큰 | top-k 3, 청크 800자, `max_tokens` 400, **질문 해시 캐시**, 작은 모델 | 08_ |
| 평가 | 토큰 | 규칙 기반 채점(LLM-as-judge 미사용), 캐시 재사용 | 09_ |

> ⚠️ 리소스 모니터는 **웨어하우스 크레딧만** 통제합니다. AI 함수·Cortex Search 는
> 서버리스 과금이라 상한이 걸리지 않습니다. 09_ [4] 의 사용량 뷰로 따로 보십시오.

> ⚠️ 이 자료는 절감률을 **측정하지 않았습니다.** 위 표는 "무엇이 과금 단위를 줄이는가" 의
> 정성 설명입니다. 작성 시점 1회 관찰값은 09_ 의 "작성 시점 참고값" 에만 있으며 기준값이 아닙니다.

### 3.2 핵심 개념

| 개념 | 요지 |
|------|------|
| 디렉터리 테이블 + 스트림 | 스테이지 파일 목록을 테이블처럼 보고, 스트림으로 추가·삭제분만 읽는다. 파일을 지우면 `DELETE` 로 잡힌다 |
| Triggered Task | `SCHEDULE` 없이 `WHEN SYSTEM$STREAM_HAS_DATA` 만 둔다. 기본 최대 30초에 1회 실행 |
| `AI_PARSE_DOCUMENT` | `OCR`(기본, 텍스트) / `LAYOUT`(표·구조 보존). `return_error_details=TRUE` 면 실패가 **예외가 아니라 error 객체**로 온다 |
| Snowpark UDTF | Python 클래스의 `process()` 가 행을 `yield`. 웨어하우스에서 실행, 토큰 과금 없음 |
| Cortex Search | 벡터+키워드 하이브리드. `ON` = 검색 컬럼, `ATTRIBUTES` = 필터 컬럼. 서빙 컴퓨트는 떠 있는 동안 과금 |
| `AI_COMPLETE` | 메시지 배열 형태는 **VARCHAR** 반환 (구 `COMPLETE` 는 OBJECT — 혼용 금지) |
| Snowpark DataFrame | `session.table()`·`create_dataframe(schema=…)`·`write.save_as_table()` 로 SQL 문자열 없이 처리 |
| Cortex Agent | `CREATE AGENT … FROM SPECIFICATION` (YAML: models / orchestration.budget / instructions / tools / tool_resources). `cortex_search` 도구는 `id_column`·`title_column` 으로 인용을 만든다 |
| 간접 프롬프트 인젝션 | 검색된 문서 안의 지시문. 문서는 **데이터**로 넘기고(system 에 넣지 않음) 문서 속 지시를 따르지 않는 규칙을 둔다 |
| 보조 역할(secondary roles) | `ALL` 이면 `USE ROLE` 후에도 다른 역할 권한이 합쳐진다. 권한 시험 시 `USE SECONDARY ROLES NONE` |

### 3.3 SP 조립형(08_) vs Cortex Agent(10_) — 언제 무엇을 쓰는가

이 자료는 RAG 를 두 방식으로 만듭니다. **어느 쪽이 정답이라는 뜻이 아닙니다.** 요구에 따라 고릅니다.

| 기준 | 08_ `SP_ASK` (SQL 조립형) | 10_ `DOC_AGENT` (Cortex Agent) |
|------|------|------|
| 구성 요소가 보이는가 | ✅ 검색·프롬프트·생성·캐시를 직접 작성 → **학습에 적합** | 오케스트레이션이 내부에서 일어남 (응답 JSON 으로 관찰) |
| 운영 서빙 경로 | ⚠️ `SEARCH_PREVIEW` 는 공식 문서상 **미리보기·검증용** | ✅ REST/`DATA_AGENT_RUN`, CoWork 연결 |
| 도구가 여러 개 | 직접 분기 코드를 짜야 함 | ✅ 도구 선택을 에이전트가 수행 |
| 여러 턴 대화 | ❌ 한 번 묻고 끝 | ✅ messages 로 이전 턴 전달 |
| 권한 모델 | `EXECUTE AS OWNER` — SP 사용 권한 = 검색 대상 전체 접근 | 호출자 역할에 검색 서비스 USAGE 필요 (없으면 도구 제외 + 경고) |
| 호출당 토큰 (10_ 1회 관찰) | 입력 약 600~750 추정 / 출력 상한 400 | 입력 약 39,000 (대부분 프롬프트 캐시) / 출력 약 550 |
| 반복 질문 캐시 | ✅ 답변 캐시 (LLM 0회) | 없음 |
| 비용 상한 장치 | TOP_K, max_tokens, 캐시 | budget(초·토큰), max_results, 오케스트레이션 모델 |

> **판단 기준(권장).** 도구가 검색 하나이고 FAQ 형 반복 질문이 많으며 비용이 최우선이면 08_ 방식에
> 운영 API(REST/Python) 검색을 붙이는 구성이 유리할 수 있습니다. 여러 도구(정형 데이터 분석 등),
> 여러 턴 대화, CoWork 노출, 역할별 권한 분리가 필요하면 Agent 가 맞습니다.
> 토큰 수치는 1회 관찰이며 요율(캐시 토큰 포함)은 Service Consumption Table 에서 확인하십시오.

### (b) 기존 객체의 속성 변경 — 2건

| 대상 | 변경 | 문서 | 사전 값 기록 | 원복 |
