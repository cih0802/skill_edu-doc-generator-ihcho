## 1. 접두사 잔여물 검사 — 전부 0행이어야 합니다

```sql
SHOW DATABASES  LIKE 'KSM_%';
SHOW WAREHOUSES LIKE 'KSM_%';
SHOW ROLES      LIKE 'KSM_%';
SHOW ROLES      LIKE 'AAD_%';
SHOW USERS      LIKE 'KSM_%';
SHOW USERS      LIKE 'EMP_F%';
```

## 3. 🔴 계정 보안 상태 원복 검증 — 개수 대조로는 잡히지 않습니다

이 실습은 객체만 만든 것이 아니라 **계정의 보안 상태를 바꿉니다.**
아래는 위 개수 대조를 통과해도 별도로 확인해야 합니다.

| 항목 | 확인 방법 | 정리 후 | 판정 |
| :--- | :--- | :---: | :---: |
| 로그인 페이지의 SSO 버튼이 사라졌는가 | 로그아웃 후 로그인 화면 확인 (95_ 5절과 대조) | | |
| SCIM 베어러 토큰이 무효화되었는가 | `AAD_SCIM_INTEGRATION` 부재 확인 | | |
| 계정 레벨 권한 위임이 사라졌는가 | `KSM_HR_SYNC_ADMIN` / `AAD_PROVISIONING_ROLE` 부재 확인 | | |
| 자동 계정 비활성화 태스크가 사라졌는가 | 태스크 2개 부재 확인 | | |
| 토큰 사본을 폐기했는가 | 메모·티켓·채팅 확인 | | |

```sql
-- 권한 위임 잔여 확인 — 역할이 없으면 오류가 나는 것이 정상입니다
SHOW GRANTS TO ROLE KSM_HR_SYNC_ADMIN;
SHOW GRANTS TO ROLE AAD_PROVISIONING_ROLE;
--   두 쿼리 모두 "does not exist" 오류가 나야 정상입니다
--   결과: ______
```

> 🔴 **토큰 값을 `SELECT` 했다면 쿼리 이력에 남습니다.** 이력은 삭제할 수 없습니다.
> 인티그레이션 `DROP` 으로 토큰 자체는 무효화되므로 실질적 위험은 해소되지만,
> 이력에 값이 남는다는 사실은 기록해 두십시오.

## 4. 사용자 속성 원복 검증

```sql
DESCRIBE USER IDENTIFIER(CURRENT_USER());
```

| 속성 | 실습 전 (95_) | 정리 후 | 판정 |
| :--- | :--- | :--- | :---: |
| `DEFAULT_ROLE` | | | |
| `DEFAULT_WAREHOUSE` | | | |
| `DEFAULT_SECONDARY_ROLES` | | | |

> 📌 **이 실습은 정상 경로에서 사용자 속성을 변경하지 않습니다.**
> 따라서 위 3개는 실습 전과 같아야 합니다. 다르다면 `03_` 의 `SSO_LOGIN_ONLY`
> 주석을 해제해 실행했을 가능성이 있습니다. `98_` PART E-1 로 원복하십시오.
>
> ⚠️ `DEFAULT_WAREHOUSE` 가 `KSM_AUTH_WH` 로 남아 있으면 삭제된 웨어하우스를
> 가리키는 상태입니다. 실습 전 값으로 되돌리십시오.

## 6. 미검증으로 남는 항목 (이 실습의 구조적 한계)

정리와 별개로, 아래는 실습 자체가 검증할 수 없는 항목입니다.

| 항목 | 이유 |
| :--- | :--- |
| 실제 Entra ID SSO 로그인 왕복 | 인증서가 더미이므로 이 설정으로 로그인은 성공하지 않습니다 |
| 실제 JWT 로 External OAuth 인증 | RSA 공개키가 더미이며 대응 개인키가 없습니다 |
| Azure Portal SCIM 프로비저닝 동기화 | Entra ID 테넌트가 필요하며 Snowflake 외부 작업입니다 |

이 항목들은 **인티그레이션이 "생성" 되었다는 것만 확인**된 것입니다.
인증 왕복이 검증된 것으로 해석하지 마십시오.
