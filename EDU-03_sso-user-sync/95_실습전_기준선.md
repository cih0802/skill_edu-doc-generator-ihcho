## 2. 🔴 접두사 충돌 검사 — 기존 객체를 덮어쓰지 않기 위해

이 실습은 `KSM_` 과 `AAD_` 접두사를 사용합니다.
**결과가 하나라도 있으면 진행하지 말고 접두사를 바꾸거나 담당자에게 확인하십시오.**

```sql
SHOW DATABASES  LIKE 'KSM_%';
SHOW WAREHOUSES LIKE 'KSM_%';
SHOW ROLES      LIKE 'KSM_%';
SHOW ROLES      LIKE 'AAD_%';
SHOW USERS      LIKE 'KSM_%';
SHOW USERS      LIKE 'EMP_F%';
```

| 검사 | 결과 행 수 | 0 인가? |
| :--- | :---: | :---: |
| `KSM_%` 데이터베이스 | | |
| `KSM_%` 웨어하우스 | | |
| `KSM_%` 역할 | | |
| `AAD_%` 역할 | | |
| `KSM_%` 사용자 | | |
| `EMP_F%` 사용자 | | |

또한 아래 3개 이름의 시큐리티 인티그레이션이 **이미 존재하지 않는지** 확인하십시오.
존재하면 실습이 기존 설정을 건드릴 위험이 있습니다.

```sql
SHOW INTEGRATIONS;
```

## 4. 🔴 로그인 관련 사전 값 — 원복에 필요합니다

이 실습은 SSO 시큐리티 인티그레이션을 만들고, `03_` 문서에 `SSO_LOGIN_ONLY` 설정이
**주석 상태로** 포함되어 있습니다. 만약 그 주석을 해제해 실행한다면
**기존 사용자 속성을 변경**하는 것이므로 사전 값이 반드시 필요합니다.

```sql
DESCRIBE USER IDENTIFIER(CURRENT_USER());
```

| 속성 | 실습 전 값 |
| :--- | :--- |
| `DEFAULT_ROLE` | |
| `DEFAULT_WAREHOUSE` | |
| `DEFAULT_SECONDARY_ROLES` | |
| `HAS_PASSWORD` | |

> 🔴 **`SSO_LOGIN_ONLY` 를 활성화하지 마십시오.** 이 실습의 인증서는 더미이므로
> 활성화하면 해당 사용자가 **로그인할 수 없게 됩니다.**
> 주석을 유지하는 것이 안전합니다.
