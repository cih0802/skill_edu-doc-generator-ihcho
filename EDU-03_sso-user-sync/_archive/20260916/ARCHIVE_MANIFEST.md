## 3. 이 폴더 문서에 남아 있는 주요 결함 (보관 시점 기준)

개선 회차에서 확인된 것만 적는다. 근거는 **실제 실행**·컴파일·공식 문서 대조다.

| 심각도 | 원본 위치 | 결함 |
| :--- | :--- | :--- |
| 🔴 | `5.인사DB_기반_…sql` | **스트림을 소비하지 않는다.** 커서 `SELECT` 는 offset 을 전진시키지 않아 5분 태스크가 같은 건을 영구 재처리. 실측: `CALL` 2회 → 감사 로그 4행 → 8행 중복, `SYSTEM$STREAM_HAS_DATA` 계속 `TRUE` |
| 🔴 | `5.인사DB_기반_…sql` | **순수 `DELETE` 오프보딩 누락.** `WHERE METADATA$ACTION='INSERT'` 필터가 `DELETE` 를 무시. 실측: `EMP_F003` 행 삭제 후에도 `disabled = false` 로 활성 잔존 |
| 🔴 | `5.인사DB_기반_…sql` | **자정 감사 프로시저가 항상 실패.** `INSERT ... VALUES` 안에서 커서 필드 직접 참조 → `invalid identifier 'R.EMP_NAME'`. `EXCEPTION` 핸들러가 삼켜 정상 반환처럼 보이고 보고서는 0행 (2차에서 정정됨) |
| 🔴 | `5.인사DB_기반_…sql` | **부서이동이 계정에 반영되지 않는다.** `CREATE USER IF NOT EXISTS` 는 기존 계정을 갱신하지 않고 뒤따르는 `ALTER` 가 `DISPLAY_NAME` 을 설정하지 않아 옛 부서에 고정 |
| 🔴 | `5.인사DB_기반_…sql` | **미정의 `EMPLOYMENT_STATUS` 가 무기록 누락.** 3개 값이 아니면 어느 분기에도 걸리지 않아 흔적 없이 사라진다 |
| 🔴 | `7.동기화_테스트_…sql` | **정리 절차가 `[선택 실행]` 으로 표기.** 실질적으로 필수인데 선택으로 안내. 건너뛰면 자동 계정 비활성화 태스크 2개, 유효한 SCIM 베어러 토큰, 계정 레벨 권한 위임, 로그인 페이지 SSO 버튼이 잔존 |
| 🔴 | `93.성능검증…md`, `92.작업후환경비교.md` | **측정 절차 없는 성능·ROI 수치를 사실로 서술.** 게다가 해당 수치가 산출된 시점에 자정 감사는 항상 실패하고 있었으므로 성립할 수 없다 |
| 🔴 | `2.`, `3.`, `6.` | **계정 레벨 객체에 `CREATE OR REPLACE`.** 시큐리티 인티그레이션·사용자는 계정 레벨이며 동명의 사용자 자산을 통째로 덮어쓴다. `DROP` 으로 되돌아가지 않는다. 접두사 충돌 검사도 없다 |
| 🔴 | 아키텍처 가이드, 문서 제목 다수 | **총괄 합격 선언.** 제목의 `(검증 완료)`, "1~7단계 전체 실행 및 엔드투엔드 검증 완료", "100% 검증", "100% 실현 가능". 실제로는 결함 3건이 있었고 인티그레이션은 "생성" 만 검증됨 |
| 🟡 | `2.`, `6.` | SAML·OAuth 인티그레이션이 **더미 인증서·공개키**를 쓰는데 "인증 왕복이 검증된 것" 처럼 읽히게 서술 |
| 🟡 | `91.초기환경.md`, `92.작업후환경비교.md` | **스냅샷 실측값을 문서에 전사.** 작성자 계정의 2026-09-08 상태이므로 실습자 계정과 달라 대조 기준으로 쓸 수 없다 |
| 🟡 | `92.작업후환경비교.md` | DB·스키마 소유자를 `KSM_HR_SYNC_ADMIN` 으로 기재. `1.…sql` 은 `ACCOUNTADMIN` 으로 생성하므로 사실과 다르다 |
| 🟡 | `7.동기화_테스트_…sql` | 태스크가 `RESUME` 된 상태에서 수동 `CALL` 을 수행해 **시나리오 검증이 결정적이지 않다.** 사전 `SUSPEND` 안내가 없었다 |
| 🟡 | 전체 | 메타 주석 / `requires`·`next` 체인 / `00_index.md` / `01_` 정리본 / **객체 대장** / `98_` 정리 정본 / `99_` 인덱스 스크립트 부재 |
| 🟡 | 전체 | 파일 번호가 `1.`~`7.` / `91`~`93` / 무번호 3종으로 혼재하고 구분자가 `.` (규격은 `_`) |

## 4. 참고 — 원본에서 옳았던 것

아카이브 문서라도 아래는 실행 검증에서 **정확함이 확인**되었다.

| 항목 | 확인 |
| :--- | :--- |
| 위임 권한 설계 | `KSM_HR_SYNC_ADMIN` 에 부여한 권한만으로 테이블·스트림 생성이 성공 |
| 정리 **목록** 자체 | 계정 레벨 객체를 포함해 누락이 없었다. 문제는 목록이 아니라 `[선택 실행]` 표기와 위치였다 |
| SAML2 / SCIM / EXTERNAL_OAUTH 생성 구문 | 모두 실제 실행으로 생성 성공 (인증 왕복은 별개) |
| 스트림 액션 서술 | `INSERT` / `UPDATE`(쌍) / `DELETE` 동작이 실측과 일치 |
