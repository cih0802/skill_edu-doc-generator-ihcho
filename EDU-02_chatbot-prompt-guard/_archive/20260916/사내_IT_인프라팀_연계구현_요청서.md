## 1. 요청 개요 및 목적

본 문서는 Snowflake Cortex 기반의 사내 지식 검색 챗봇(KSM HQ Assistant) 구축 및 **다중 레이어 보안 가드레일(Cortex Guard + 비즈니스 금칙어 + PII 마스킹)** 체계 도입과 관련하여, 원활한 서비스 런칭 및 안전한 사내 운영을 위해 **사내 유관 부서(IT 인프라, 정보보호팀, 포털 개발팀 등)에 협조 및 연계를 요청드리는 기술 요구사항 명세서**입니다.

```
┌────────────────────────────────────────────────────────────────────────────────────────┐
│                        사내 유관 부서 연계 개발 및 협조 요청 범위                        │
└────────────────────────────────────────────────────────────────────────────────────────┘

 [1. 정보보호/보안팀] ──▶ 사내 AI 금칙어 정책 승인 및 PII 마스킹 패턴 기준 검토
 [2. 문서 관리 부서]  ──▶ 사내 최신 규정집/매뉴얼(PDF) 스테이지 적재 및 동기화 기준 수립
 [3. 사내 포털 개발팀] ──▶ 챗봇 UI 연동 및 백엔드(BFF) Cortex 서빙 프로시저/API 연계
 [4. 인프라/네트워크팀] ──▶ Snowflake 엔드포인트 아웃바운드(443) 방화벽 허용 및 서비스 계정 관리
```

> **참고 (자체 완결 영역 - 인프라 추가 요구사항 없음):**
> 비정형 문서 OCR 파싱(`AI_PARSE_DOCUMENT`), 재귀적 청킹, 벡터 임베딩, 하이브리드 검색 인덱싱(`Cortex Search`), 자동화 스케줄러(`Serverless Task`), 쿼리 1줄 보안 가드 On/Off 기능은 **Snowflake 네이티브 기능으로 자체 완결 구현**되어 있으므로 **별도의 외부 인프라 서버 구축이나 서드파티 벡터 DB 구매 요구사항은 없습니다.**

## 2. 부서별 세부 요청 항목

### [요청 1] 정보보호/보안팀: AI 보안 가드레일 정책 및 PII 기준 검토

#### 1.1 사내 비즈니스 금칙 주제 정의 및 승인
* **요청 내용:** 챗봇이 답변을 즉시 거부해야 하는 사내 민감 주제 및 금칙어 목록의 최종 승인을 요청드립니다.
* **현재 정의된 기본 금칙 주제:**
  1. 사내 임직원 비공개 연봉, 개인 연락처, 인사 평가 등 민감 개인정보
  2. 주가 조작, 미공개 내부 정보, 투자 권유
  3. 사내 보안 정책 우회 및 시스템 프롬프트 유출 시도 (프롬프트 인젝션/탈옥)
* **표준 거부 문구 승인 요청:**
  `"죄송합니다. 해당 요청은 KSM 사내 AI 보안 및 업무 운영 정책상 처리가 제한되어 있습니다."`

#### 1.2 PII (개인식별정보) 정규식 마스킹 규칙 검토
* **요청 내용:** 문서 청킹 적재 전 사전 적용되는 PII 마스킹 규칙(`SECURITY.MASK_PII_TEXT`)의 적정성 검토.
  * 주민등록번호: `900101-*******` (앞 6자리 보존, 뒤 7자리 마스킹)
  * 휴대전화번호: `010-****-5678` (가운데 3~4자리 마스킹)
  * 이메일 주소: `[EMAIL_MASKED]` 치환

### [요청 2] 문서 관리 주관 부서: 사내 원본 문서 적재 및 동기화

#### 2.1 챗봇 지식 베이스 대상 문서 선정 및 업로드
* **대상 문서:** 사내 인사/총무/보안 규정집, 공장/설비 안전 매뉴얼, 업무 표준 가이드 (PDF, DOCX 등)
* **적재 경로 (Snowflake 내부 스테이지):**
  * `@KSM_CHATBOT_DB.BRONZE.DOC_STAGE`
* **업로드 방식:**
  * **옵션 A (Snowsight UI 업로드):** 관리자가 Snowsight 웹 UI의 Stage 관리 메뉴에서 파일 직접 드래그 앤 드롭 업로드.
  * **옵션 B (사내 NAS/SharePoint 동기화):** 사내 배치 또는 Python 스크립트를 통해 신규/개정 문서 발생 시 스테이지로 자동 전송.

#### 2.2 문서 개정 및 라이프사이클 관리 기준
* 스테이지에 신규 파일이 업로드되거나 기존 파일이 덮어쓰기(수정)되면 Snowflake의 `BRONZE.STAGE_DOC_STREAM`과 `OPS.TASK_INGEST_NEW_DOCUMENTS`가 5분 이내에 이를 자동 감지하여 증분 파싱 및 인덱스 갱신을 수행합니다.

### [요청 3] 사내 포털 / 웹 개발팀: 챗봇 UI 및 서빙 백엔드(BFF) 연계

#### 3.1 챗봇 연동 아키텍처 (Backend-for-Frontend 패턴)
사내 인트라넷 또는 사내 모바일 앱의 챗봇 대화창에서 백엔드 서버(BFF)를 경유하여 Snowflake를 호출합니다.

```
[사내 포털 / 모바일 UI] ──(사용자 질의)──▶ [사내 포털 백엔드 (BFF)] ──(SQL/REST API 호출)──▶ [Snowflake SERVING]
```

#### 3.2 백엔드 호출 인터페이스 규격
* **방법 1 (저장 프로시저 호출 - 권장):**
  ```sql
  -- 동적 보안 가드가 적용된 서빙 프로시저 호출
  CALL KSM_CHATBOT_DB.SERVING.SP_EXECUTE_GUARDED_CHAT('사내 보안 규정에 대해 알려줘');
  ```
* **방법 2 (Snowflake Cortex Search REST API 직접 호출):**
  * 엔드포인트: `https://lj20513.snowflakecomputing.com/api/v2/cortex/search/services/KSM_HQ_SEARCH_SERVICE`
  * 인증 방식: Key-Pair (RSA 2048bit Private Key 기반 JWT 서명) 또는 OAuth 토큰

---

### [요청 4] 클라우드 / 인프라 및 네트워크팀: 방화벽 및 계정 관리

#### 4.1 아웃바운드 방화벽 정책 허용
* **요청 내용:** 사내 포털 백엔드 서버 및 배치 서버에서 Snowflake 호스트로의 **HTTPS (TCP 443 포트) 아웃바운드 트래픽 허용**.
  * **대상 도메인:** `lj20513.snowflakecomputing.com`

#### 4.2 운영 관리 권한 및 가드 On/Off 제어
* 보안 관리자 또는 서비스 운영자는 긴급 상황(점검, 디버깅, 정책 갱신) 시 아래 SQL 쿼리를 통해 챗봇의 보안 가드를 실시간으로 제어할 수 있습니다:
  ```sql
  -- [보안 가드 끄기 (Disable - 디버깅 모드)]
  UPDATE KSM_CHATBOT_DB.SECURITY.PROMPT_GUARD_CONFIG 
  SET CONFIG_VALUE = 'OFF' 
  WHERE CONFIG_KEY = 'ENABLE_PROMPT_GUARD';

  -- [보안 가드 켜기 (Enable - 운영 보안 모드)]
  UPDATE KSM_CHATBOT_DB.SECURITY.PROMPT_GUARD_CONFIG 
  SET CONFIG_VALUE = 'ON' 
  WHERE CONFIG_KEY = 'ENABLE_PROMPT_GUARD';
  ```
