# 95. 실습 전 환경 기준선 (Baseline)

정리(`98_`) 후 이 기록과 대조해 **실습이 계정에 흔적을 남기지 않았음**을 증명합니다.

> 🔴 **이 문서에는 값이 채워져 있지 않습니다.** 의도된 것입니다.
> 계정 상태는 계정마다 다르고 시간이 지나면 달라지므로, 작성자의 값을 전사해 두면
> 즉시 거짓이 되어 대조 기준으로 쓸 수 없습니다. **아래 쿼리를 직접 실행해
> 빈칸을 채우십시오.**

- **실행 시점**: `02_환경초기화_및_RBAC구성.sql` 을 실행하기 **전**
- **필요 권한**: `ACCOUNTADMIN`
- **부작용**: 없음 — 모두 조회 전용입니다
- **예상 소요 시간**: 약 5분

## 5. 🔴 실습이 변경할 계정 파라미터 — 반드시 기록

이 값들은 `10_` 에서 변경되며 **`DROP` 으로 되돌아가지 않습니다.**
기록하지 않으면 `98_ [7]` 의 원복이 불가능합니다.

```sql
SHOW PARAMETERS LIKE 'AI_SETTINGS' IN ACCOUNT;
SELECT "key", "value", "default", "level" FROM TABLE(RESULT_SCAN(LAST_QUERY_ID()));

SHOW PARAMETERS LIKE 'CORTEX_ENABLED_CROSS_REGION' IN ACCOUNT;
SELECT "key", "value", "default", "level" FROM TABLE(RESULT_SCAN(LAST_QUERY_ID()));
```

### 5.1 `AI_SETTINGS`

| 항목 | 값 |
|------|-----|
| `value` | `______________________` |
| `level` | `______________` (비어 있으면 계정 미설정) |

원복 분기 판정 (`98_ [7.1]` 에서 사용):

- ☐ 경우 1) `10_ [2.2]` 를 실행하지 않을 예정 → 원복 불필요
- ☐ 경우 2) 실습 전에도 이미 같은 guardrails 설정 → 원복 불필요
- ☐ 경우 3) 실습 전이 **비어 있음 / 미설정** → `ALTER ACCOUNT UNSET AI_SETTINGS`
- ☐ 경우 4) 실습 전에 **다른 YAML** 이 설정됨 → 아래에 전문 보관 후 재설정


### 5.2 `CORTEX_ENABLED_CROSS_REGION`

| 항목 | 값 |
|------|-----|
| `value` | `______________` |
| `level` | `______________` |
| 제품 기본값 | `DISABLED` |

원복 분기 판정 (`98_ [7.2]` 에서 사용):

- ☐ 이미 활성(`ANY_REGION` 등) → `10_ [2.1]` **건너뜀**. 98_ 에서도 손대지 않음
- ☐ `DISABLED` → `10_ [2.1]` 수행 필요. 98_ 에서 `DISABLED` 로 원복
- ☐ 다른 리전 그룹 → 원래 값 기록: `______________`

> 💡 **제품 기본값과 이미 같다면 변경 자체가 불필요합니다.**
> 불필요한 변경을 만들지 않는 것이 원복보다 안전합니다.

## 6. 기준선 확정 체크리스트

- ☐ 0~5 의 모든 빈칸을 채웠다

- ☐ 🔴 `AI_SETTINGS` 실습 전 값과 원복 분기를 기록했다
- ☐ 🔴 `CORTEX_ENABLED_CROSS_REGION` 실습 전 값과 원복 분기를 기록했다
- ☐ Edition 을 확인했다 (Standard 이면 `10_` 생략)
