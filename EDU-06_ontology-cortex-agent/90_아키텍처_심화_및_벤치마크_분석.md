## 1. 벤치마크 실험 배경 및 평가 결과

도메인 온톨로지가 없는 관계형 데이터베이스 환경에서는 사용자의 자연어 질문이 도메인 상속 관계나 유의어를 포함할 때 SQL 번역 오류가 빈번히 발생합니다.

Snowflake 엔지니어링 팀은 **Cell Ontology (CL)**와 **PRISM 암세포 약물 반응 데이터셋**을 결합하여 고난도 22개 질의에 대해 4가지 아키텍처의 성능을 5회 반복 측정하였습니다.

### 벤치마크 결과 비교표

| 에이전트 구성 (Agent Setup) | 도구 개수 | 평균 점수 (/2.0) | 성공률 (%) | 분산 (Run-to-run Variance) |
| :--- | :---: | :---: | :---: | :---: |
| **Standard Semantic View (Baseline)** | 1 | 0.93 | 50.0% | 보통 |
| **Baseline with Knowledge Graph** | 7 | 1.14 | 60.0% | 높음 (오케스트레이션 실패 발생) |
| **Baseline with Flattened GraphRAG** | 2 | 1.38 | 70.0% | **가장 낮음 (매우 안정적)** |
| **GraphRAG + Terminology Mappings** | 2 | 1.55 | 78.2% | 보통~높음 |

## 2. 핵심 아키텍처 교훈 및 트레이드오프

### ① 데이터 계층을 먼저 해결하라 (Fix the data layer first)
- 성능 향상의 약 **80%**는 복잡한 프롬프트 엔지니어링이 아니라 **하위 속성(조직 목록 등)을 상위 노드로 롤업 집계한 전처리 데이터 계층**에서 발생했습니다.
- 사전 계산된 프로파일 인덱스가 갖춰지면 에이전트의 불필요한 다단계 추론 부담이 제거됩니다.

### ② 도구가 적을수록 더 견고하다 (Fewer tools can also give good results)
- 7개 도구를 가진 순수 지식 그래프 에이전트는 이론상 정확한 계층 탐색이 가능하지만, LLM이 도구 선택 순서에서 실수를 범하여 실행 분산이 커집니다.
- **2개 도구(Cortex Search + Cortex Analyst/SQL)**로 구성된 Flattened GraphRAG는 에이전트의 결정 공간을 단순화하여 일관된 고성능을 제공합니다.

### ③ 타겟 용어 매핑으로 라스트 마일 해결 (Targeted hardcoding closes the last gap)
- "internal organ lining"과 같이 계층 순회만으로 도출하기 어려운 복합 용어(Composite Terms)나 도메인 은어는 시스템 프롬프트 수준의 명시적 매핑 규칙을 통해 마지막 정확도 갭을 메울 수 있습니다.

## 3. 엔터프라이즈 도입 권장 절차

1. **온톨로지 적재**: OWL/RDF/CSV 형태의 도메인 온톨로지를 `KG_NODE`, `KG_EDGE`로 Snowflake에 수용.
2. **배치 프로파일링**: Dynamic Table 또는 Scheduled Task를 활용하여 계층 롤업 비정형 프로파일(`KG_FLATTENED_PROFILES`) 생성.
3. **Cortex Search 인덱싱**: 하이브리드 검색 서비스를 배포하여 유의어 처리 자동화.
4. **Cortex Agent 연계**: Semantic View 및 Search 서비스를 연결하고, 고유 예외 규칙을 프롬프트에 주입.
