## 1. 벤치마크 실험 배경 및 평가 결과 (외부 인용 · 미측정 · 미확인)

도메인 온톨로지가 없는 관계형 데이터베이스 환경에서는 사용자의 자연어 질문이 도메인 상속 관계나 유의어를 포함할 때 SQL 번역 오류가 생길 수 있습니다.

인용 자료에 따르면 Snowflake 엔지니어링 팀은 **Cell Ontology (CL)** 와 **PRISM 암세포 약물 반응 데이터셋**을 결합한 22개 질의로 4가지 구성을 5회 반복 비교하였습니다.

| 에이전트 구성 (Agent Setup) | 도구 개수 | 평균 점수 (/2.0) | 성공률 (%) | 분산 (Run-to-run Variance) |

## 2. 핵심 아키텍처 교훈 및 트레이드오프

### ① 데이터 계층을 먼저 해결하라 (Fix the data layer first)
- 인용 자료는 개선의 큰 몫이 프롬프트가 아니라 **하위 속성(조직 목록 등)을 상위 노드로 롤업한 전처리 데이터 계층**에서 나왔다고 설명합니다. (1차 판의 "약 80%" 는 출처를 확인하지 못해 삭제)
- 이 실습의 관찰(`08_` 표본 1회): 계층 정보가 필요한 Q1 에서 Baseline 은 `('skin','esophagus')` 만 조회했고, Grounded 는 프로파일의 롤업 조직 4개를 그대로 썼습니다.

### ② 도구가 적을수록 더 견고하다 (Fewer tools can also give good results)
- 인용 자료는 7개 도구 KG 에이전트의 도구 선택 순서 실수로 실행 분산이 커졌다고 설명합니다.
- 이 실습은 7-도구 구성을 만들지 않았으므로 이 주장은 확인하지 않았습니다. 05_ 의 프로시저를 generic 도구로 붙이면 직접 비교해 볼 수 있습니다.

### ③ 타겟 용어 매핑으로 라스트 마일 보완 (Targeted hardcoding closes the last gap)
- "internal organ lining" 처럼 계층 순회만으로 도출하기 어려운 복합 용어는 orchestration 지침의 명시적 매핑 규칙으로 고정할 수 있습니다.
- 이 실습의 관찰(`08_` Q2): Baseline 도 상식으로 비슷한 조직을 골랐지만 필터에 `liver` 가 섞였고, Grounded 는 규칙대로 3개 조직만 썼습니다. 매핑 규칙은 "정답을 새로 만든다" 기보다 **결과를 고정**하는 역할로 관찰되었습니다.

## 3. 엔터프라이즈 도입 권장 절차

1. **온톨로지 적재**: OWL/RDF/CSV 형태의 도메인 온톨로지를 `KG_NODE`, `KG_EDGE`로 Snowflake에 수용.
2. **배치 프로파일링**: Dynamic Table 또는 Scheduled Task를 활용하여 계층 롤업 비정형 프로파일(`KG_FLATTENED_PROFILES`) 생성.
3. **Cortex Search 인덱싱**: 하이브리드 검색 서비스를 배포하여 유의어 처리 자동화.
4. **Cortex Agent 연계**: Semantic View 및 Search 서비스를 연결하고, 고유 예외 규칙을 프롬프트에 주입.
