# 11. 트러블슈팅

---


## A-1. 진단의 출발점 — 3단 확인

문제가 생기면 **아래 순서로** 좁혀 나갑니다. 순서를 건너뛰면 시간이 더 걸립니다.

```
1) 객체가 존재하고 상태가 정상인가?   → SHOW / DESCRIBE
2) 무슨 오류가 났는가?                → Event Table 조회
3) 어느 계층의 문제인가?              → 인프라 / 네트워크 / 소스 / 설정
```

### 1단계 — 상태 확인

```sql
USE ROLE OPENFLOW_EDU_ADMIN_RL;

SHOW OPENFLOW DEPLOYMENTS;
SHOW OPENFLOW RUNTIMES IN ACCOUNT;
SHOW OPENFLOW CONNECTORS IN SCHEMA OPENFLOW_EDU_DB.OPENFLOW_EDU_SCH;

DESCRIBE OPENFLOW RUNTIME
  OPENFLOW_EDU_DB.OPENFLOW_EDU_SCH.OPENFLOW_EDU_RUNTIME;
DESCRIBE OPENFLOW CONNECTOR
  OPENFLOW_EDU_DB.OPENFLOW_EDU_SCH.PG_CDC_CONNECTOR;
```

기대 상태: Runtime `ACTIVE` + `server_url` 채워짐, Connector `RUNNING`.

### 2단계 — Event Table 조회

```sql
-- 최근 1시간 오류/경고
SELECT TIMESTAMP
     , RESOURCE_ATTRIBUTES:"snow.openflow.connector.name"::string AS connector
     , RECORD:severity_text::string                              AS severity
     , VALUE:formattedMessage::string                             AS message
FROM OPENFLOW_EDU_DB.OPENFLOW_EDU_SCH.EVENTS
WHERE TIMESTAMP > DATEADD('hour', -1, CURRENT_TIMESTAMP())
  AND RECORD:severity_text::string IN ('ERROR', 'WARN')
ORDER BY TIMESTAMP DESC
LIMIT 100;
```

```sql
-- 오류 메시지별 빈도 (반복되는 근본 원인 찾기)
SELECT VALUE:formattedMessage::string AS message
     , COUNT(*)                       AS cnt
     , MIN(TIMESTAMP)                 AS first_seen
     , MAX(TIMESTAMP)                 AS last_seen
FROM OPENFLOW_EDU_DB.OPENFLOW_EDU_SCH.EVENTS
WHERE TIMESTAMP > DATEADD('hour', -6, CURRENT_TIMESTAMP())
  AND RECORD:severity_text::string = 'ERROR'
GROUP BY 1
ORDER BY cnt DESC
LIMIT 20;
```

전용 Event Table 을 연결하지 않았다면 `SNOWFLAKE.TELEMETRY.EVENTS` 를 조회하세요.

### 3단계 — 계층 판별

| 증상 | 의심 계층 |
|------|-----------|
| Deployment / Runtime 생성 자체가 실패 | 인프라 · 권한 · 계정 활성화 |
| `UnknownHostException`, `Connection refused`, `SocketTimeout` | 네트워크 (Network Rule / EAI) |
| `password authentication failed`, `no pg_hba.conf entry` | 소스 인증 · 접근 제어 |
| `No publication exists`, UPDATE 미반영 | 소스 CDC 설정 |
| `Invalid connector configuration file` | 설정 파일 (config.json) |
| RUNNING 인데 데이터가 안 옴 | 소스 CDC 설정 또는 Warehouse 권한 |

## A-2. 단계별 오류 대응표

### 02번 단계 — 사전 준비

| 증상 | 원인 | 조치 |
|------|------|------|
| `SHOW OPENFLOW CONNECTOR DEFINITIONS` 가 SQL 컴파일 오류 | 계정에 Gen 2 미활성화 | Snowflake 계정 팀에 Gen 2 활성화 요청. 실습 진행 불가 |
| `CREATE ROLE` 권한 오류 | 현재 Role 이 `ACCOUNTADMIN` 아님 | `USE ROLE ACCOUNTADMIN;` |
| Openflow UI 가 좌측 메뉴에 없음 | Trial 계정 등에서 UI 미노출 | SQL 경로로 진행 (이 실습의 기본 경로). UI 필요 시 계정 팀 문의 |

### 03번 단계 — Deployment / Runtime

| 증상 | 원인 | 조치 |
|------|------|------|
| `CREATE OPENFLOW DEPLOYMENT` 권한 오류 | Trial 계정에서 Openflow 미활성화 | 계정 팀 문의 |
| `CREATE OPENFLOW DEPLOYMENT` 가 한도 오류 | 계정당 Snowflake Deployment 3개 초과 | `SHOW OPENFLOW DEPLOYMENTS` 로 확인 후 불필요한 것 삭제. 보조 Role 을 켜지 않으면 안 보이는 Deployment 가 있을 수 있음 (`USE SECONDARY ROLES ALL`) |
| `SYSTEM$WAIT_FOR_STABLE_OPENFLOW_DEPLOYMENTS` 타임아웃 | 프로비저닝이 아직 진행 중 | 몇 분 후 **WAIT 함수만** 재실행. ❌ `CREATE` 를 재실행하지 마세요 |
| Deployment 가 실패 상태 | 프로비저닝 오류 | Openflow UI 에서 오류 메시지 확인 후 재시도 |
| Runtime 이 ACTIVE 인데 `server_url` 이 비어 있음 | 프로비저닝은 됐지만 정상 기동 실패 | Openflow UI 에서 Runtime 상태 확인. 재생성이 필요할 수 있음 |
| Runtime 버전이 2026.8.25.11 미만 | 런타임이 오래됨 | 업그레이드 후 커넥터 생성 |
| Runtime 사이즈를 바꾸고 싶음 | — | **tier 는 변경 가능**: `ALTER OPENFLOW RUNTIME <n> SET NODE_TYPE_TIER = 'S2';`<br>**node type 은 변경 불가** → 새 Runtime 생성 + 커넥터 재설치 |

### 05번 단계 — 네트워크 / Secret

| 증상 | 원인 | 조치 |
|------|------|------|
| `invalid value for property 'VALUE_LIST'` | **EGRESS 규칙은 생성 시점에 DNS 검증**. 호스트가 해석되지 않음 | placeholder 를 실제 호스트로 교체. 소스 DB 기동 확인. `nslookup <host>` 로 검증. ⚠️ 가짜 호스트로 만들어 두고 나중에 고치는 것은 불가능 |
| `SocketTimeoutException` | DNS 는 됐지만 TCP 연결 실패 | Network Rule 에 **포트**가 포함됐는지 확인. 소스 방화벽 / Security Group 확인 |
| `UnknownHostException` | Runtime 이 해당 도메인에 접근 불가 | ① Network Rule 에 host:port 존재 ② EAI 가 규칙 참조 ③ EAI 가 Runtime 에 연결 ④ execute-as Role 에 EAI USAGE |
| `Insufficient privileges` on `CREATE INTEGRATION` | Role 에 계정 권한 없음 | `GRANT CREATE INTEGRATION ON ACCOUNT TO ROLE ...` (ACCOUNTADMIN 으로) |
| Secret 이 위저드 드롭다운에 안 보임 | `TYPE = PASSWORD` 로 생성됨 | `DROP SECRET` 후 `TYPE = GENERIC_STRING` 으로 재생성 |
| 사설망 소스에 도달 불가 | `MODE = EGRESS` 로는 사설 호스트 불가 | DCP(`DATA_CONNECTIVITY_PROXY_EGRESS`) 또는 outbound PrivateLink(Business Critical 이상) 또는 BYOC 배포 |

### 07~08번 단계 — 설정 / 커밋 / 기동

| 증상 | 원인 | 조치 |
|------|------|------|
| `Invalid connector configuration file at location: 'config.json'` | **백슬래시 이중화 누락** (`\` → `\\`) | 07번 5-3(1) 재수행. ⚠️ 같은 파일로 커밋을 반복해도 해결되지 않음 |
| `COPY INTO` 가 문법 오류 (문자열 미종료) | 설정값의 아포스트로피 미이스케이프 (`'` → `''`) | 백슬래시 문제와 **다른 실패 지점**. JSON 이 스테이지에 도달하기 전에 깨짐 |
| 커밋 후 config 가 깨짐 / 크기가 다름 | `COMPRESSION = NONE` 누락으로 gzip 처리됨 | `COPY INTO` 결과의 `input_bytes` = `output_bytes` 확인. 다르면 `REMOVE` 후 재실행 |
| Snowsight 에서 `PUT` 이 `Permission denied by user` | Snowsight 는 PUT 차단 | `COPY INTO` + `COPY FILES` 경로 사용. `snow` CLI 우회도 차단됨 |
| `GET` 이 `ENOENT` | 로컬 디렉터리 없음 | 존재하는 디렉터리 지정 (`/tmp` 등) |
| 커밋 후 `GET .../versions/live/config.json` 이 "version live is not found" | 커밋이 live 버전을 소비함 | `SHOW VERSIONS IN OPENFLOW CONNECTOR <fqn>` → `versions/version$N/config.json` 을 GET |
| `ABORT` 가 "Cannot abort live version ... no default version exists" | 한 번도 커밋되지 않은 커넥터 | ABORT 불가. live config 를 덮어쓰고 다시 커밋 |
| `ADD LIVE VERSION FROM LAST` 실패 | 커넥터가 아직 `STOPPING` 상태 | `SYSTEM$WAIT_FOR_OPENFLOW_CONNECTOR_STATUS(600,'STOPPED',...)` 로 대기 후 재시도 |
| `UPDATE_FAILED` | config.json 이 유효하지 않음 | 원인 수정 → `ADD LIVE VERSION FROM LAST` → 재업로드 → `COMMIT` |

### START_FAILED — PostgreSQL 오류 메시지별

| `formattedMessage` | 원인 | 조치 |
|--------------------|------|------|
| `FATAL: database "X" does not exist` | JDBC URL 의 DB 이름 오류 | URL 수정 후 재커밋 |
| `FATAL: password authentication failed` | 자격증명 오류 | Secret 값 또는 `Source Database User` 확인 |
| `PSQLException: Connection refused` | 네트워크 또는 호스트 오류 | Network Rule 의 host:port 확인 |
| `No publication exists` | 소스에 PUBLICATION 없음 | 04번 5장 수행 |
| `Cannot create PoolableConnectionFactory` | 드라이버 문제 또는 연결 실패 | JAR 업로드 여부, `assetIds` 파일명, URL 확인 |
| `FATAL: no pg_hba.conf entry` | 소스가 Runtime IP 접속을 허용하지 않음 | `pg_hba.conf` 또는 Security Group 수정 |
| SSL 관련 오류 | URL 에 `?sslmode=require` 누락 | URL 수정 |

### 09번 단계 — 데이터가 오지 않음

| 증상 | 확인 순서 |
|------|-----------|
| 대상 스키마/테이블이 생성되지 않음 | ① Connector `RUNNING`? ② execute-as Role 에 `CREATE SCHEMA on CDC_LAB_PG_DB`? ③ Event Table 오류 확인 |
| 스냅샷이 진행되지 않음 | ① Warehouse 가 재개 가능? (execute-as Role 에 `OPERATE`) ② `Ingestion Type = full`? |
| INSERT 만 반영, UPDATE/DELETE 미반영 | ① 소스 테이블에 PK 있는가 (`relreplident`) ② PUBLICATION 의 `pubupdate`/`pubdelete` = `t` |
| 전혀 반영되지 않음 | ① `pg_publication_tables` 에 해당 테이블 있는가 ② `pg_replication_slots` 의 `active` = `t` 인가 ③ Warehouse 가 suspend 상태로 멈춰 있는가 |
| 반영이 매우 느림 | `Merge Task Schedule CRON` 확인. Warehouse 재개 시간 고려. Runtime tier 상향 검토 |

소스 측 확인 쿼리 (PostgreSQL):

```sql
-- 발행 대상 테이블
SELECT * FROM pg_publication_tables WHERE pubname = 'openflow_pub';

-- 복제 슬롯 상태 (active 가 t 여야 함)
SELECT slot_name, plugin, slot_type, active, restart_lsn,
       pg_size_pretty(pg_wal_lsn_diff(pg_current_wal_lsn(), restart_lsn)) AS lag
FROM pg_replication_slots;

-- replica identity
SELECT c.relname, c.relreplident
FROM pg_class c JOIN pg_namespace n ON n.oid = c.relnamespace
WHERE n.nspname = 'public' AND c.relkind = 'r';
```

## A-3. Openflow Connectors Dashboard 활용

Snowsight 에 Openflow 메뉴가 노출되는 계정이라면 GUI 진단이 훨씬 빠릅니다.

**Ingestion » Openflow » Connector Observability** 탭

제공 정보: 커넥터별 Healthy/Unhealthy 상태, 테이블별 복제 상태(Active/Failed),
복제 단계(New / Snapshot Load / Incremental Replication), 마지막 적재 시각,
오류 분포, 평균 처리량.

최소 버전 요구사항:

| 대상 | 최소 버전 |
|------|-----------|
| Snowflake 배포 | 1.26.0 |
| BYOC 배포 | 1.36.0 |
| Runtime | 2026.3.17.13 |
| PostgreSQL 커넥터 | 0.39.0 |
| MySQL 커넥터 | 0.33.0 |

Event Table 에 대한 최소 읽기 권한이 필요합니다.
